# 요구사항

## 사용자

- Telegram OpenID Connect로 로그인한다.
- 최초 로그인 후 Telegram User ID를 내부 사용자와 연결한다.
- 이름, 부서, 직책, 입사일을 본인 정보에서 확인/수정한다.
- 당해 전체 연차, 사용 연차, 잔여 연차를 확인한다.
- 기본 화면은 월간 달력이다.
- 일반 사용자는 달력에서 본인의 일정만 확인한다.
- 달력에서 날짜를 눌러 휴가 신청 팝업을 연다.
- 현재 조회 월의 신청 내역과 승인 상태를 달력 옆/아래에서 바로 확인한다.
- 휴가 항목을 눌러 상세 내용을 확인한다.
- 휴가 신청과 전체 신청 내역 화면은 분리한다.
- 신청 시작일/종료일 기본값은 오늘이며 종료일은 시작일보다 빠를 수 없다.
- 반차는 오전/오후를 선택하며 반차 선택 시 종료일을 별도로 선택하지 않는다.
- 신청 사유는 기본 사유 선택 + 추가 사유 입력으로 구성한다.
- 잔여 연차보다 많이 신청해도 접수할 수 있고 부족 경고를 표시한다.
- 승인 전 신청은 사용자가 취소할 수 있다.

## 휴가 유형

- `V`: 연차, 1.0일 차감
- `H`: 반차, 0.5일 차감, 오전/오후 구분
- `G`: 공가, 연차 미차감
- `S`: 병가, 연차 미차감
- `A`: 대체휴가, 연차 미차감
- 기존 Excel의 `P` 개인 휴가는 신규 신청 유형으로 사용하지 않는다.

## 관리자

- 사용자 등록, 수정, 활성/비활성 처리를 한다.
- 사용자의 이름, 입사일, 부서, 직책, Telegram 연결 상태를 관리한다.
- 관리자/사용자 권한을 지정한다.
- 마지막 1명의 활성 관리자는 사용자로 강등하거나 비활성화할 수 없다.
- 권한 또는 계정 상태가 변경되면 해당 계정의 기존 로그인 세션은 다음 요청에서 무효화한다.
- 전체 직원의 달력과 현재 월 신청 내역을 확인한다.
- 휴가 신청을 승인 또는 반려한다.
- 승인된 휴가를 취소하고 연차/반차 차감을 자동 복원한다.
- 일정 변경이 필요하면 승인 취소 후 관리자 대리 신청으로 새 일정을 등록한다.
- 직원 대신 휴가를 신청할 수 있다.
- 입사일 기반 자동 연차 발생분을 동기화한다.
- 당해 총 연차를 특정 값으로 고정하고 필요 시 고정을 해제한다.
- 연차 이월/추가 조정을 원장에 기록한다.
- 직원별/월별 휴가 집계를 검색·필터하고 그래프로 확인한다.
- 공휴일 API를 갱신하고 회사 휴무일을 관리한다.
- 주요 관리 작업의 Audit Log를 확인한다.
- 회사명/프로그램명, 로고, 대표색, 라이트/다크/시스템 테마를 관리한다.
- 월~일 중 실제 주 근무 요일을 설정한다. 비근무 요일은 달력에서 강조하고 신규 휴가 일수 계산에서 제외한다.
- 관리자 환경설정에서 전체 서비스 데이터를 초기화하고 설치 마법사부터 다시 시작할 수 있다.
- Telegram 연결 정보, 회사 공용 그룹 Chat ID, 공휴일 ServiceKey를 환경 설정에서 관리한다.
- 직원용 Telegram Bot 링크와 서비스 로그인 링크를 복사할 수 있다.

## Telegram

- Authorization Code Flow + PKCE 방식의 Telegram OIDC 로그인을 사용한다.
- `openid profile telegram:bot_access` scope를 사용한다.
- 로그인 사용자의 안정적인 Telegram User ID를 내부 사용자와 연결한다.
- 휴가 신청 시 휴가 사유와 잔여 연차 경고를 포함한 관리 알림을 활성 관리자 개인 Telegram으로 전송한다.
- 승인/반려/승인 취소 시 신청자에게 개인 결과 알림을 전송한다.
- 승인된 휴가 일정과 승인 취소된 일정은 회사 공용 Telegram 그룹에 공유한다.
- 회사 공용 그룹에는 휴가 신청 사유, 잔여 연차 경고, 관리자 검토 메모 등 관리용 정보를 전송하지 않는다.
- Telegram 메시지 전송 실패가 핵심 DB 처리 자체를 롤백하지 않게 한다.
- 최초 설치에서는 @BotFather에서 Bot Token과 Login Widget Client ID/Secret을 발급받는다.
- 현재 서비스 host를 기준으로 Allowed Origin과 Redirect URI를 자동 계산한다.
- 최초 관리자 개인 채팅과 회사 공용 그룹은 Bot API 최근 채팅 탐색으로 연결하며 수동 ID 입력 fallback을 제공한다.
- Bot API만으로 새 Telegram 그룹 생성/자동 가입을 구현하지 않는다. 별도 사용자 MTProto 세션을 요구하는 구조는 현재 범위에서 제외한다.

## 초기 설치

- DB 접속 가능한 최소 `config/config.php`와 Composer 의존성 설치 후 Setup Wizard를 사용한다.
- 설치 페이지는 CLI에서 생성한 setup key로 보호한다.
- 신규 설치는 migration 없이 현재 `database/schema.sql`만 사용한다.
- schema 초기화는 중간 실패 후 재실행할 수 있어야 한다.
- 설치 순서는 DB → Telegram Bot/OIDC → 최초 관리자 개인 채팅/회사 공용 그룹 → 최초 관리자 로그인 → 공휴일 API → 완료이다.
- 설치 완료 후 setup key를 삭제하고 일반 사용자의 Setup 접근을 차단한다.
- 기존 운영 DB는 활성 관리자 계정이 있으면 legacy 설치로 인식해 setup 완료 상태로 자동 이행한다.
- 설치 완료 후 bootstrap 관리자 ID는 일반 권한 변경을 덮어쓰는 영구 관리자 권한으로 사용하지 않는다.

## 연차 계산

- 입사일을 원본 데이터로 사용한다.
- 1년 미만은 월별 발생 이벤트를 관리한다.
- 1년 이상은 기본 15일과 장기근속 가산을 적용하며 최대 25일이다.
- 근태 데이터를 직접 수집하지 않으므로 월 개근/연간 80% 출근 요건 충족을 전제로 자동 발생한다.
- 실제 예외는 관리자 조정으로 보정한다.
- 법정 발생과 이월/수동 조정/고정 Override를 분리한다.
- 승인된 연차/반차만 사용 원장에 반영한다.
- 승인 취소 시 reversal로 기존 차감을 복원한다.

## 휴일/날짜 처리

- 기본 주 근무 요일은 월~금이며 관리자가 월~일 단위로 변경할 수 있다.
- 설정된 비근무 요일은 휴가 일수 계산에서 제외한다.
- 공휴일 DB의 `is_public_holiday=1` 날짜는 휴가 차감일에서 제외한다.
- 표시 전용 휴일은 달력에 표시하되 휴가 차감 제외 여부와 분리한다.
- 기간 신청은 실제 차감 날짜를 `leave_request_days`에 저장한다.
- 회사 휴무일을 별도 source로 관리한다.
- 비근무 요일/공휴일/회사 휴무일/오늘은 달력에서 시각적으로 강조한다.

## 설정 및 보안

- DB 접속 정보와 웹 서버 기본 설정은 `config/config.php`에 둔다.
- Telegram Client Secret/Bot Token, 공휴일 ServiceKey는 Setup/관리자 환경설정에서 DB 관리값으로 저장할 수 있다.
- Secret/Token/API Key 기존 값은 관리 화면에 다시 노출하지 않는다.
- Audit Log에는 실제 비밀값을 기록하지 않는다.
- 연결 실패 화면에 외부 요청 원문 예외를 그대로 노출하지 않는다.
- 실제 `config/config.php`, setup key, runtime upload 파일은 Git에서 제외한다.
- DB 접근은 PDO prepared statement를 사용한다.
- 세션 쿠키는 Secure/HttpOnly/SameSite를 적용한다.
- 관리자 기능은 서버 측 권한 검사를 수행한다.
