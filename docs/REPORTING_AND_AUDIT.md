# 집계 및 변경 이력

## 연차 집계 기준

직원별 연차 현황은 `annual_leave_ledger`를 기준으로 계산한다.

- 발생: `grant`
- 이월: `carryover`
- 조정: `adjustment`
- 복원: `reversal`
- 사용: `usage`의 음수 금액을 양수 사용량으로 표시
- 잔여: 해당 연도의 모든 원장 금액 합계

따라서 관리자 화면의 수동 조정과 승인된 연차/반차 사용이 동일한 원장 기준으로 집계된다.

## 월별 휴가 집계

월별 휴가 사용량은 `leave_requests.status = approved`인 신청의 `leave_request_days`를 기준으로 집계한다.

- 실제 휴가 날짜 기준으로 월을 구분한다.
- 휴가 종류(V/H/P/S/A)별로 합산한다.
- 반차는 저장된 `amount=0.5`를 그대로 합산한다.
- 반려/취소/승인 대기 신청은 집계하지 않는다.

## 관리자 대시보드

현재 연도를 기준으로 다음 정보를 표시한다.

- 활성 직원 수
- 승인 대기 신청 수
- 법정 발생 연차 합계
- 사용 연차 합계
- 연차 원장 잔여 합계
- 현재 월 승인 휴가 일수
- 최근 변경 이력

## Audit Log

`audit_logs` 테이블에 데이터 변경이 성공한 시점의 주요 작업을 기록한다.

기록 대상:

- 직원 추가/수정
- 사용자 본인 입사일 수정
- 휴가 신청
- 승인 전 신청 사용자 취소·삭제
- 승인 휴가 사용자/관리자 취소
- 관리자 승인/반려
- 연차 발생 동기화
- 이월/수동 연차 조정
- 공휴일 API 동기화
- 수동/회사 휴일 추가·삭제

로그에는 작업자, 작업 코드, 대상 종류/ID, 필요한 비민감 세부 정보, 요청 IP, 시간이 저장된다.

비밀번호, API 키, Telegram Bot Token 같은 설정 비밀값은 기록하지 않는다.

## Excel 출력 기간 기준

휴가 Excel 내보내기의 월/연 기간은 `leave_requests.start_date`가 아니라 실제 휴가 날짜인 `leave_request_days.leave_date`를 기준으로 필터한다.

예를 들어 9월 30일~10월 1일 2일 신청을 9월 월간 Excel로 출력하면 해당 신청은 포함되며:

- 신청일수: 2.0일
- 기간내일수: 1.0일

로 표시한다. 전체 기간 출력은 저장된 모든 휴가 신청을 대상으로 한다. 승인 전 취소로 삭제된 신청은 DB에 남지 않으므로 출력 대상에도 포함되지 않는다.

## 관리자 대시보드 휴가 기준

- **현재 휴가 중**: 오늘 날짜가 `leave_request_days.leave_date`에 존재하고 신청 상태가 `approved`인 모든 휴가를 표시한다.
- 현재 휴가 중 목록은 직원명, 부서, 휴가 종류, 반차 오전/오후, 전체 신청 기간, 오늘 해당 일수를 표시한다.
- **다가오는 휴가**: 실제 첫 휴가일(`MIN(leave_request_days.leave_date)`)이 내일부터 14일 후까지인 `approved` 신청만 표시한다.
- 이미 오늘 휴가 중인 다일 신청은 다가오는 휴가에 중복 표시하지 않는다.
- 승인 대기, 반려, 취소 상태는 두 목록 모두 대상이 아니다.

## 종료된 휴가 기록 정리

관리자는 환경 설정에서 더 이상 운영 중인 휴가가 아닌 `cancelled` / `rejected` 기록을 영구 정리할 수 있다.

정리 대상:

- `leave_requests.status IN ('cancelled', 'rejected')`
- 해당 신청의 `leave_request_days`
- 해당 신청을 참조하는 `annual_leave_ledger`
- `target_type='leave_request'`이고 해당 신청 ID를 가리키는 Audit Log

보존 대상:

- `pending`
- `approved`

정리 작업은 하나의 DB 트랜잭션으로 수행하며, 완료 후 개별 삭제 대상과 무관한 요약 Audit Log `leave.closed_history_purged`를 남긴다.
